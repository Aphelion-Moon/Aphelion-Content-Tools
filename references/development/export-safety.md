# Export safety

Export is two state transitions: prepare creates an immutable staged payload and manifest without
touching the game checkout; apply revalidates that manifest against current state immediately before
the only permitted write.

## Prepare contract

Require committed canonical content and a compatible Meridian-Rift identity. The target contains
`tgstation.dme` and, when an origin exists, matches the accepted Meridian remote identity. Record the
tool revision and branch, canonical-content revision, game revision, schema and manifest versions,
catalog/projection provenance, affected stable IDs and type paths, allowed destination, and
source, base, and final hashes. Validate the generated bytes before the stage becomes visible.

## Apply contract

Apply requires a clean and conflict-free checkout, unchanged game revision, accepted schema and
manifest versions, matching canonical-content revision and staged source hash, and an unchanged base
artifact hash. Resolve the destination and enforce parent containment beneath the selected game root.
The only allowed output is
`modular_aphelion/modules/lore_overhaul/code/generated_lore_overrides.dm`.

Use an atomic replace. If any multi-step operation is added, complete rollback must restore the prior
bytes and repository state without a mixed result. Recompute and verify the final hash. Every refusal
leaves the checkout untouched and returns a specific recovery action. There is no force override for
a dirty, conflicted, stale, incompatible, or out-of-root target.

Tests use temporary repositories or a dedicated clean checkout, never a maintainer's dirty production
checkout. After success, hand review, commit, push, pull request, authentication, and complex merges to
GitHub Desktop. Failure to open GitHub Desktop does not retroactively invalidate a completed atomic
apply, but it must be reported.
