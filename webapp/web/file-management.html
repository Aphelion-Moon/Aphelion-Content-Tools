Repository operations

Database and Git

Background jobs that keep the shared data store (Lore Editor's Catalog, the Content Graph's cache, and search) in sync with the game checkout, plus the store's own health. Nothing here runs on its own except one automatic database optimize shortly after this app starts — everything else is a snapshot that only updates when you run the matching job below.

1. Catalog & validation

Run after pulling game-repo changes, or after hand-editing override JSON outside the Lore Editor UI.

Run an individual step instead

2. Content graph

Run after pulling game-repo changes, or after editing marker comments or master_files overrides directly.

3. Database maintenance

Rebuild embeddings only after changing the embedding model or recovering from an offline run. Optimize compacts and prunes the store and also runs once automatically shortly after startup.

Stage a Commit

            

              Writes the generated lore override artifact into this checkout so it's ready to commit. Three
              steps, always in order: generate builds and validates the artifact outside
              the game checkout — it never touches Meridian-Rift and is always safe to run; select
              the prepared stage to apply, defaulting to the most recently generated one; then
              apply writes it into the game checkout and opens GitHub Desktop so you can
              review the diff and commit it.
